# Refine goals into an actionable but revisable plan

For each **selected, user-approved** goal with stable `G-*` ID:

- `Outcome`: desired change in user's words, acknowledging external dependencies.
- `Why`: personal reason, or TBD.
- `Process`: 1–3 actions the user controls; propose a frequency and seek confirmation.
- `Evidence`: indicator, optional `EV-*` reference, source, baseline and target if known; no fabricated percentages.
- `Constraints`: obstacles, dependencies and explicit stop-doing choices.
- `Review`: reasonable check-in cadence and what would prompt adjustment.
- `Status`: `active`, `paused`, `completed`, or `retired`, always user-approved.

Read [goal-history](goal-history.md) before changing any existing plan. Show old → new changes, ask permission, **append** a `refined` or `adjusted` event, then update that goal's snapshot. Do not rewrite prior events or overwrite manual edits. Where baseline/target is missing, retain `TBD` and ask only if a metric will genuinely improve the decision. If goals in a legacy file lack IDs, offer voluntary migration; don't fabricate historical events.
